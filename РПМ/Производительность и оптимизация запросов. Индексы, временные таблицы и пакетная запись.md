# Понятие производительности прикладного решения
**Производительность** - способность программного решения выполнять операции за установленное время:
- Время выполнения
- Пропускная способность
- Параллельность
- Масштабируемость

# Виды производительности
- ***Клиент*** - формы, клиентский код, объём трафика и вывозы сервера
- ***Сервер*** - серверный код, обработка объектов, запросы и блокировки
- ***СУБД*** - таблицы, индексы, планы выполнения, ресурсы и параллельные операции

Правило оптимизации:
```mermaid
graph LR
	Проблема --> Измерение --> у[Узкое место] --> Изменение --> Переизмерение
```

# Причины медленных запросов
**Причина 1**: Большой объём данных (избыток)
**Причина 2**: Запросы внутри циклов
**Причина 3**: Ненужные поля
**Причина 4**: Неэффективные соединения
- Соединение больших таблиц без фильтров - плохо
- Неиндексированные поля - плохо
- Сложные подзапросы - плохо

**Причина 5**: Получение запросов через точку
**Причина 6**: Использование функций в условиях
# Базовые принципы оптимизации
1. Ограничивать объём данных
2. Фильтровать как можно раньше
3. Использовать параметры виртуальных таблиц
4. Не использовать запросы в цикле
5. Использовтаь пакет запросов
6. Учитывать тип базы

# Что такое индекс
**Индекс** - структура, позволяющая быстрее находить, сортировать и осуществлять выборку записей по определённым полям
**Где наиболее полезен**:
- В условии ГДЕ
- В условии соединения ПО
- В параметрах виртуальной таблицы
- В группировке и сортировке
- При поиске уникального значения
# Составные индексы
***Пример***: `Организация + Склад + Номенклатура`
**Левый префикс индекса**
Для индекса `А + В + С` наиболее подходящими обычно является условия:
- `А` - эффективно
- `А + В` - эффективно
- `А + В + С` - эффективно
- Только `С` - не эффективно
# Индексы в соединениях
При соединение важно, чтобы поле поиска было проиндексированно. Соединение по ссылкам обычно автоматически проиндексированны
## Цена избыточных индексов:
- Время записи
- Размер БД
- Нагрузка на СУБД
# Индексы а регистрах
Индексы формируются с учётом структуры регистра и его измерений
> [!tip] Примечание
> Порядок измерений влияет на эффективность запросов

# Индексы в временных таблицах
Полезен если:
- Имеет большой объём данных
- Участвует в соединении
- Используется в условии В
- Многократно читается

# Временная таблица
**Временная таблица** - особый объект СУБД, который создаётся и наполняется данными во время выполнения пакетного запроса для ускорения/оптимизации обработки информации
Назначение:
- Разделить запрос
- Сохранить промежуточный результат
- Сокращение набора данных
- Повторно использовать данные

# Создание временной таблицы
Создаётся [[#Временная таблица|ВТ]] используя конструкцию `ПОМЕСТИТЬ [ИмяТаблицы]`

# Плюсы и минусы
**Плюсы**:
- Разделение сложной задачи
- Уменьшение объёма
- Повторное использование результата
- Индексация промежуточных данных
- Улучшение сопровождаемости

**Не стоит**:
- Помещать все поля
- Загружать значительный объём данных без необходимости
- Создавать [[#Временная таблица|ВТ]] в цикле
- Копировать без причины
- Использовать несколько таблиц для простой задачи

# Пакетные запросы
**Пакетные запросы** - несколько частей запроса, выполняемых в рамках одного запроса
Из результатов можно:
- Передать через временную таблицу
- Получать по индексу
- Обрабатывать последовательно

# Плюсы и минусы
**Избыточен**:
- Задача решается 1 запросом
- Промежуточные результаты не используется
- [[#Временная таблица|ВТ]] не нужны
- Данных мало
- Усложнение кода не даёт измеримого выигрыша

# Пакетная и порционная запись
**Пакетная запись** - сохранение группы изменений одной операцией или несколькими крупными порциями

# Порционная запись
При большом объём данных запись одним набором может привести к:
- Повышенному потреблению памяти
- Длительной транкзакции и блокировкам
- Росту журнала транкзакций
- Сложному повтору операции при ошибке

# Транкзакции при пакетной записи
Транкзакция позволяет объединить несколько операций в одну логическую группу
# Контроль транкзакций и блокировок
**Блокировка** - временно ограничивает доступ других операций к данным, изменяемым текущей транкзакцией
**Как уменьшить влияние**:
- Сократить размер и длительность транкзакции
- Выполнять расчёты до начала транкзакции
- Читать только необходимые данные
- Записывать данные порциями
- Не выполнять долгие отчёты и пользовательский ввод внутри транкзакции
- Переносить критические проверки ближе к моменту записи

# Практический алгоритм оптимизации
1. Зафиксировать проблему
2. Измерить время
3. Проверить текст запроса
4. Проверить индексы
5. Проверить [[#Временная таблица|ВТ]]
6. Проверить запись
7. Повторить измерение
