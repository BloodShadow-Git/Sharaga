# Назначение СКД в архитектуре отчёта
**Система компоновки данных** - встроенный мощный механизм платформы 1С, который предназначен для быстрого и гибкого построения аналитических отчётов
СКД строит отчёты на базе:
- Наборов данных
- Параметров и отборов
- Группировок и ресурсов
- Вычисляемых и пользовательских полей
- Настроек оформления
- Пользовательских вариантов

**Схема компоновки данных** - базовый объект и декларативный шаблон, определяющий источники информации, логику объединения и правила построения отчётов:
- Какие источники и поля доступны
- Какие вычисления возможны
- Какие параметры и группировки можно использовать

**Настройки компоновки** - параметры в системе 1С, которые определяют, как именно будут отображаться и структурироваться данные:
- Что вывести
- Как сгруппировать и отсортировать
- Какие отборы и оформления применить

# Общая архитектура отчёта
1. Наборы данных
2. Схема данных
3. Поля и вычисления
4. Настройка варианта
5. Компоновка данных
6. Результат (Табличный документ)

# Состав сложного отчёта [[#Назначение СКД в архитектуре отчёта|СКД]]
**Набор данных** - источник информации, который определяет, откуда и как отчёт получает сведения
Основные варианты:
- Запрос
- Объект
- Объединение

**Поля** - базовые элементы данных, с помощью которых формируются, настраиваются и выводятся отчёты
**Ресурс** - поле, значение которого автоматически расчитывается на основе детальных записей, входящих в определённую группировку
**Группировки** - элементы структуры отчёта, которые объединяют и упорядочивают данные по определённым полям, а также вычисляют по ним промежуточные и общие итоги
**Параметры** - специальные инструменты управления отчётом, которые позволяют динамически изменять логику работы запросов, фильтровать данные, задавать периоды и передавать значения из пользовательской формы:
- Обязательными/необязательными
- Пользовательскими/Вычисляемыми
- Недоступные для изменения
- Связанные с параметрами виртуальных таблиц

# Настройки определяют текущий результат
Управляют:
- Выбранными полями
- Группировками
- Отборами и сортировками
- Параметрами
- Условным оформлением
- Расшифровками
- Расположением итогов
- Внешним видом отчёта

> [!tip] Примечание
> В сложном отчёте доступные настройки следует ограничивать

# Вариант отчёта
**Вариант отчёта** - отдельный набор настроек, который определяет, как именно будут представленные данные одного и того же запроса
Может включать:
- Поля и группировки
- Отборы и сортировки
- Значения параметров
- Условное оформление
- Структуру расшифровки
- Настройки вывода

Позволяют:
- Не создавать отдельный отчёт для каждой формы представления
- Быстро переключать структуру результата
- Сохранять рабочие настройки пользователя
- Создавать стандартные представления
- Разграничивать доступ к сложным настройкам
- Адаптировать отчёт под разные должности

1. **Стандартный** - основной, базовый набор настроек и структуры, который разработчик закладывает в конфигураторе по умолчанию для отображения данных
	 Должен:
	- Соотвествовать основной задаче отчёта
	- Быстро формироваться
	- Содержать ключевые поля
	- Быть понятным без доп. настроек
	- Иметь безопасный объём данных
2. **Пользовательский** - сохранённая конфигурация настроек отчёта, созданная или изменённая самим пользователем, а не заложенная разработчиком в конфигураторе
	Может:
	- Изменять группировки
	- Добавить отборы
	- Изменить сортировку
	- Добавить поля
	- Изменить оформление

> [!tip] Примечание. Важно различать
> **Вариант отчёта** - полная структура представления
> **Пользовательские настройки** - индивидуальные изменения пользовтателя
> **Текущие настройки** - параметры, действующие сейчас
> **Настройки разработчика** - настройки, заданные в конфигураторе

# Ограничения вариантов
Доступ можно ограничивать по:
- Пользователю/роли
- Назначению
- Доступным полям
- Составу настроек
- Возможности редактирования

# Рекомендации по проектированию вариантов:
- Давать имена по смыслу
- Создавать один понятный стандартный вариант
- Не дублировать представления без необходимости
- Не включать лишние поля
- Проверять доступность данных под разными ролям
- Отделять настройки представления от логики отчёта

# Настройки пользователя и разработчика
**Настройки разработчика** - базовый шаблон структуры отчёта, который задаётся программистом в конфигураторе
**Настройки пользователя** - набор параметров, отборов, группировок и других правил, которые конечный пользователь может изменять без изменения конфигурации
Изменения могут быть:
- Временные
- Сохранённые в пользовательском варианте
- Восстановленными при следующем открытии отчёта
- Применяемыми только к текущем пользователю

# Обязательные и необязательные настройки
**Обязательные** - настройки структуры компоновки, без которых механизм не сможет сформировать и вывести итоговый отчёт
**Необязательные** - параметры или элементы отбора, которые могут исключаться из выполнения запроса, если пользователь не заполнил их или отключил их использование

# Безопасность пользовательских настроек
Необходимо:
- Ограничить данные на уровне RLS
- Проверять права на сервере
- Не полагаться только на видимость полей
- Отделять пользовательский отбор от ограничения доступа
- Тестировать отчёт под разными ролями

# Пользовательские поля
**Пользовательское поле** - поле, которое пользователь может создать или настроить средствами отчёта без изменения исходного запроса и конфигурации
**Отличие**:
- ***Поле запроса*** - часть схема данных и формируется на уровне источника
- ***Пользовательское поле*** - создаётся в [[#Назначение СКД в архитектуре отчёта|СКД]] и относиться к конкретному представлению отчёта

# Когда расчёт нужно перенести в запрос:
- Участвует в соединении или отборе большого объёма
- Используется в нескольких отчётах
- Требуется оптимизация на уровне СУБД
- Связанно с виртуальной таблицей
- Требует предварительной агрегации

# Виды пользовательских полей:
- **Поле-выражение** - настраиваемый элемент, значение которого вычисляется по специальной формуле на языке выражений
- **Поле выбора** - элемент управления, предназначенный для хранения и быстрого выбора одного конкретного значения из заранее подготовленного списка вариантов
- **Тип результата** - число, строка, дата, булево значение, ссылка или составной тип. Определяет корректность сортировки, группировки, сравнения и отображения

# Встроенные функции [[#Назначение СКД в архитектуре отчёта|СКД]]
Применяются в:
- Вычисляемых и пользовательских отборах
- Отборах
- Условном оформлении
- Выражениях ресурсов

Задачи:
- Обработка `NULL` значений
- Условные расчёты
- Работа с датами и строками
- Преобразование типов
- Вычисление итогов

**`ЕСТЬNULL(Значение, ЗначениеПоУмолчанию)`**
```
ВЫБОР
	КОГДА Условние1
		ТОГДА Результат1
	КОГДА Условие2
		ТОГДА Результат2
		ИНАЧЕ РезультатПоУмолчанию
КОНЕЦ
```
**`НАЧАЛОПЕРИОДА(<Дата>, <ТипПериода>)`**
**`РАЗНОСТЬДАТ(<Дата1>, <Дата2>, <Тип>)`**
**`ДЛИНАСТРОКИ(<Строка>)`**
**`ПОИСКСТРОКИ(<Строка>, <ПодстрокаПоиска>, <НачальнаяПозиция>)`**
**`ПОДСТРОКА(<Строка>, <НачальнаяПозиция>, <Длина>)`**
**`ВРЕГ(<Строка>)`**
**`НРЕГ(<Строка>)`**
Объединение: **`<Строка1> + <Строка2> + ... + <СтрокаN>`**

# Когда вычислять в запросе, а когда в [[#Назначение СКД в архитектуре отчёта|СКД]]
[[#Назначение СКД в архитектуре отчёта|СКД]]:
- Оформить результат
- Классифицировать данные для конкретного отчёта
- Создать простой показатель
- Вывести текстовое пояснение или условную подпись
- Добавить пользовательские показатели и поля текущего варианта
